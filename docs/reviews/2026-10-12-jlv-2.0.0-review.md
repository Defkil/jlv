## Correctness and robustness

### Terminal text and viewer

- **High — quadratic sanitizer work.** `packages/jlv/src/terminal-text.ts`, control-string patterns: repeated
  unterminated C1 OSC/DCS introducers made the regex retry every remaining suffix. Measured 4,000/8,000/16,000
  OSC introducers at approximately 44/170/691 ms before the fix, sufficient to stall a viewer or plain output
  with a legal large input line. A new control-string introducer now ends an unfinished candidate; incomplete
  text is escaped and complete following sequences are stripped. The same samples took approximately 2/2/2 ms
  afterwards; 131,072 introducers took 25 ms. The regression uses a child-process deadline, which can interrupt
  synchronous regex work, and checks all five control-string introducers. Fixed in the terminal/viewer commit
  listed below.
- **Medium — C selected the wrong record on later viewports.** `packages/jlv/src/tui/main-panel.ts`,
  `moveToCenterViewportLine()`: `(start + height) / 2` selected a row above the midpoint and could scroll the
  viewport backwards. It now adds half the viewport height to its start. Existing characterization assertions
  explicitly preserved the bug; they now prove the correct row and unchanged viewport.
- **Low — custom filter values lost colons.** `packages/jlv/src/tui/main-panel.ts`, `openCustomFilter()`:
  `split(':', 2)` dropped text after a second colon. Splitting at the first separator preserves times, URLs and
  other values. A regression proves that a longer unmatched value no longer matches its shortened prefix.
- **Low — suffix clipping detached combining marks.** `packages/jlv/src/tui/formatting.ts`,
  `cutStartToWidth()`: a discarded base could leave its mark attached to the ellipsis. Marks now wait for their
  base to fit. Tests cover narrow Latin and CJK suffixes.

All four are fixed in `44afaa1`. Final references: `terminal-text.ts:24`, `tui/main-panel.ts:770`,
`tui/main-panel.ts:585` and `tui/formatting.ts:73`, respectively, under `packages/jlv/src`.

### Input, output and lifecycle

- **High — debug logging could truncate an input.** `packages/jlv/src/application.ts:737` and
  `packages/jlv/src/tui/blessed-boundary.ts:16`: an unchecked `--log` path reached neo-blessed's default-truncating
  write stream. Creation errors were asynchronous/unhandled and the backend never closed its logger. The
  application now creates an exclusive regular-file destination, rejects input/existing/save aliases before
  opening the screen, listens for errors and closes its own logger. The backend receives the owned stream
  through its write-only logger slot, never a file path. Tests prove the input stays unchanged, existing logs
  are refused, new logs close after q, uncreatable paths fail cleanly and save aliases are refused. Machine
  output and an empty `--log=` create no debug file. This intentionally tightens the CLI; README/help/checklist
  now describe it.
- **High — save overwrite checked a path before a truncating open.** `packages/jlv/src/output.ts:209`:
  replacing the destination with an input alias between validation and `open('w')` could destroy the input.
  The open now avoids `O_TRUNC`, checks the opened handle's identity/type, then truncates. `O_NONBLOCK` avoids
  waiting if a POSIX FIFO appears at the name. Existing direct/hardlink/path-spelling tests and a new nonregular
  destination test pass. The exact concurrent replacement race was reviewed statically; there is no flaky
  timing-dependent claim that it was reproduced.
- **Medium — unfinished source iterators were abandoned.** `packages/jlv/src/application.ts:155`, `merge()`:
  strict failure or output closure left readers paused on yielded batches or pending reads, retaining producers
  and followed-file handles. Early exit now aborts the inputs before returning every unfinished iterator. A
  two-lane regression with a pending reader proves both finalizers run; original errors remain preserved.
- **Medium — cancellation could hang during the final stdout flush.** `packages/jlv/src/output.ts:114` and
  `packages/jlv/src/application.ts:376`: a signal released a blocked write but final flushing was uncancellable
  after signal listeners had gone. Separate output cancellation now interrupts the final drain while listeners
  remain active. Never-completing output tests exercise both a buffered write and an accepted write followed by
  a stalled flush; both return 130.
- **Medium — tiny chunks defeated the framing memory bound.** `packages/jlv/src/input/lines.ts:83`:
  keeping one Buffer per chunk made a legal 1 MiB unfinished line in one-byte chunks consume roughly
  **114.05 MiB extra heap / 253.10 MiB RSS** on the old head. A geometrically growing contiguous pending buffer
  used **0.075 MiB extra heap / 44.17 MiB RSS** in the same Node 26 `--expose-gc` probe. The large tiny-chunk
  regression and existing BOM, LF/CRLF, partial UTF-8 and oversized-line cases pass.
- **Medium — follow used stale stat/open information and lacked cancellation inside draining.**
  `packages/jlv/src/input/follow.ts:61`: a replacement between path stat and open could supply another file's
  size, open a non-file or leak the descriptor if handle stat failed; a FIFO could block opening on POSIX.
  Continuously growing files could also postpone cancellation until a drain reached EOF. Handle stat now
  supplies the checked regular-file type/size, failed handles are closed, opens are nonblocking, and each read
  checks cancellation. A large-file abort regression proves cancellation while draining; replacement races
  were inspected statically.
- **Low — completed runs retained borrowed stdout listeners.** `packages/jlv/src/output.ts:148`: disposal
  removes writer listeners after drain/close, retaining a late-EPIPE handler only while cancelled output remains
  pending. Three repeated runs on a borrowed stdout prove zero error/close listeners afterwards.
- **Low — an already-aborted write was queued.** `packages/jlv/src/output.ts:93`: aborted writes now discard
  their text. The old assertion that preserved this behavior was corrected.

All eight are fixed in `ee34bb2`. Original rotation, truncation, UTF-8 framing, independent keyboard,
plain fallback, EOF, EPIPE and signal tests remain green. Size-based polling still cannot detect truncate-and-
regrow past the previous size entirely between polls; this is documented and accepted for 2.0.0. Rotation
drains the old handle as observed at the switch; it cannot promise to collect arbitrarily later writes to a
renamed generation. Raw console behavior remains a human terminal gate below.

### Formats, configuration and plugins

- **Medium — asynchronous/non-boolean plugin predicates matched records accidentally.**
  `packages/jlv/src/plugins.ts`, `checkPlugin()`: Boolean coercion accepted promises and arbitrary truthy values;
  a rejected promise could terminate the process outside normal error handling. Results now must be synchronous
  booleans. Invalid asynchronous results have their rejection observed and are reported through the existing
  predicate failure path, which excludes the record and returns exit code 1. Tests include an async rejection.
- **Medium — normalization errors still produced records.** `packages/jlv/src/ingestion.ts`,
  `Ingestion.accept()`: an error diagnostic increased the skip count but the offending entry was still stored and
  emitted, including after the first strict error. Such entries are now rejected; strict mode reports only through
  the first error and preserves preceding valid output. Regression tests exercise both modes and store contents.
- **Low — CSV accepted one excess content byte.** `packages/jlv/src/formats/csv.ts`, `CsvFramer.#complete()`:
  the extra byte allowed for CRLF also admitted an ordinary content byte. The content is now checked against the
  exact byte limit before decoding, retaining the CRLF allowance. Tests cover ASCII, multibyte UTF-8 and CRLF.
- **Low — a BOM-prefixed JSON configuration failed.** `packages/jlv/src/configuration.ts`, `readJson()`:
  discovery recognized the JSON file but parsing kept its leading UTF-8 BOM. The parser now removes that BOM;
  a file-based regression proves discovery and application of its values.
- **Low — a plugin predicate named `__proto__` disappeared.** `packages/jlv/src/plugins.ts`, `checkPlugin()`:
  assigning it to an ordinary object changed the prototype instead of defining a predicate. `Object.fromEntries`
  now preserves the own key, including duplicate-name detection. Tests verify both the key and its callable result.
- **Low — plugin values could change when serialized.** `packages/jlv/src/record.ts`, `jsonProblem()`:
  dates, maps, custom prototypes, getters and sparse arrays passed the JSON check despite producing changed
  serialized data or executing accessors. Validation now requires plain/null-prototype objects, dense ordinary
  arrays and data properties, without reading getters. The follow-up check also covers non-enumerable `toJSON`
  hooks and array prototypes. Ordinary JSON fields named `toJSON` remain allowed when they are not callable.
- **Low — segment-array paths invoked accessors.** `packages/jlv/src/field-path.ts`, `childOf()`:
  own-key checks alone allowed getters, contrary to the documented lookup contract. Segment lookups now require
  own data descriptors, as legacy text paths already did. A getter regression proves it is never called.

The first seven fixes are recorded in `218408b`; serialization-hook validation has a follow-up commit below.
Final implementation references under `packages/jlv/src` are `plugins.ts:218`, `ingestion.ts:419`,
`formats/csv.ts:95`, `configuration.ts:240`, `plugins.ts:218`, `record.ts:423` and `field-path.ts:65`, respectively.
`8055034` completes serialization-hook validation.
The store and incremental record view were inspected for arena growth/wrap, eviction, stable selection, missing
sort values, filter revisions and cached field values. Existing deterministic wrap/merge tests check retained
bytes and equivalence to a fresh order. No unresolved correctness finding remains there. Retained record bytes
and count are bounded; they are not a promise to cap total process RSS, especially with field sorting or plugins.
JSON nesting is rejected beyond 64 levels before recursive normalization/serialization. Automatic probing is
bounded and preserves replayed bytes; formats remain selected per source, not guessed anew for every line.

## Code quality and tests

The compiler uses strict NodeNext TypeScript with unchecked-index and exact-optional checks, no unused code,
no emit on errors and `skipLibCheck: false`. A source scan found no application `any`, double casts through
`unknown`, `@ts-ignore` or equivalent escapes. The neo-blessed import and private logger adaptation remain in
the typed backend boundary; callbacks and parsed/plugin values are narrowed there or at their data boundary.

The ESLint composition remains neostandard, typescript-eslint `strictTypeChecked` and Unicorn recommended.
Every exception has a scoped rationale: unavailable Node 22 APIs, standard TSDoc layout, legitimate JSON/backend
nulls, synchronously registered `node:test` calls, plan module names, flat-config composition, control-character
regexes and legacy go-to-line prefix parsing. The one new inline exception observes a rejected async predicate
inside a synchronous contract; it cannot await the invalid result. Unused disables/configurations are errors.
No broad lint exclusion was introduced.

The review replaced assertions that preserved the wrong C midpoint and added adversarial contract, byte-limit,
backpressure, iterator cleanup, file-destination and sanitizer tests. Documentation examples without an explicit
`echo $?` previously compared output only; they now also require exit code 0. Expected failing examples keep
their explicit status checks. Headless terminal tests exercise actual backend cells and output, selection and
dialog cleanup; they do not prove a physical terminal's rendering or Windows console keyboard behavior.
The prior 10,000-cycle lifecycle and multi-gigabyte input proofs remain historical evidence in the phase results,
not fresh results claimed by this review.
